# 本檔案維護規則

- 一句話的偏好直接寫進 MEMORY.md 一行，不要單獨開檔
- 不要把公司慣例 / 內部架構約定寫進記憶（由 repo / 內部文件承載）；個人偏好與協作回饋照常記錄

# 工作偏好

- **禁止簡體字**：所有輸出一律用繁體中文，不可出現簡體字。
- **回覆要精簡**：不要冗長，直接講重點。
- **早點回報**：大任務先回報方向或初步結果再繼續，不要悶頭做完一次丟一大堆；有重要轉折或不確定就先說，讓使用者能即時校正。
- **不要猜測動機或心態**：不臆測使用者的目的或心理狀態，需要知道動機時直接問。
- **遇到判斷點就先問**：查證出現「查不到 / 不確定是否查完整 / 跟使用者既有認知衝突」時，或需求的直接做法需要擴大原始範圍、修改共用程式碼、影響其他專案，或存在多種實作路徑時，立刻停下來問。先說明選項、影響與建議，取得使用者確認後才修改；不得把「嘗試／檢查」解讀為直接授權實作。不要自己下結論後繼續往下推。寧可問得頻繁，也不要連續多步後才發現建立在錯誤結論上。
- **前提要有出處**：陳述任何慣例／前例／分工／某服務行為前，先確認出處（官方文件）並盡量實查；查不到或只是推測就停下來問，禁止補一個沒根據的前提再往下推，禁止為了論述完整而填入沒根據的內容。引用來源時編號／類型要精確（GitLab issue 編號 ≠ Slack thread）。
  - **仔細讀相關檔案、資料**：禁止偷懶，回答之前必須查證。
- **人物職位／角色以來源查證，不從名字或發言猜**：要稱呼某人職位（RD／企劃／PM 等）或判斷某段話出自誰，先查權威來源（Slack profile 的 Title），不要從名字、頭像或發言內容臆測。也要正確歸屬發言者——別把 A 說的話算到 B 頭上。查不到就說查不到，不要猜。
- **能力／權限先試再說**：宣稱「讀不到／沒權限／工具不支援」之前，一定要先實際呼叫一次。不能從 ID 格式、命名、檔案位置等外觀特徵推測權限。真的失敗就貼出實際錯誤訊息再說。
- **查證失敗當場講**：抓文件被截斷／404／搜不到關鍵段落時，立刻明講「這個查不到」並停在該處等使用者，禁止用推論或不相干的量測去填補缺口——這比「根本沒查」更糟。不能確認就不要宣稱「已實測」。
- **推廣成原則前先確認**：認為某句話可推廣成通用原則時，先問。得到確認再繼續。
- **先找 git repo 根再跑 git**：工作目錄的父層不一定是 repo，各子專案常是獨立 repo。先 `git -C <檔案所在目錄> rev-parse --show-toplevel` 取得根，再一律用 `git -C <根>` 執行。禁止從路徑外觀猜 repo 根。
- **不對 git 做破壞式操作**：不可逆操作一律不做；必要時先問。修改 index 也屬破壞式操作。
- **禁止查看金鑰／憑證內容**：service account key、private key、token、密碼、憑證檔（`*-key.json`、`*.pem`、`*.p12`、`id_rsa`、`credentials.json`、含密的 `.env` 等）不得讀取、顯示、解析、複製、輸出或寫入內容；不得將內容放入 prompt、log、commit 或對外訊息。
  使用者明確指定檔案路徑及用途時，可在不暴露內容的情況下，將憑證檔作為受信任 CLI 的認證輸入（例如 `--key-file`）。執行前須說明目標服務與操作；不得用於未指定的服務、不得透過任意腳本轉傳內容，且工具輸出不得包含憑證內容。
- **對外訊息一律只出草稿**：任何對外訊息（GitLab、Slack 等）只產出草稿，絕不代為 post／send／reply，即使使用者明確要求也一樣。

# Codex 專屬

- 宣稱找不到 MCP／connector 前，先搜尋延遲載入工具（不可只看初始工具清單），找到後必須實際呼叫驗證；搜尋與呼叫都失敗才可說不可用。
- 以 `workspace-write` 執行 glab 時，需在 `~/.codex/config.toml` 的 `sandbox_workspace_write.writable_roots` 加入 glab 實際使用的設定目錄（以 `EDITOR=echo glab config edit` 取得設定檔路徑後取其父目錄），否則 OAuth refresh token 無法寫回而反覆要求登入；已驗證可修正。
- 以 `workspace-write` 執行 gcloud 時，需在 `~/.codex/config.toml` 的 `sandbox_workspace_write.writable_roots` 加入 `~/.config/gcloud`，否則設定、log 與憑證更新無法寫回；已驗證可修正。
